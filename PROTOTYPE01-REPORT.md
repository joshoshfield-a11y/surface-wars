# Surface Wars — Prototype 01 Report

Date: 2026-10-30. Scope: spec Milestone 01 only, plus a validated data
catalog for the massive roster. New folder `~/workspace/surface-wars/`.
The original `~/workspace/scrap-dungeon/` was not touched. No commits,
pushes, publishing, or APK packaging were done (working tree only).

## What was built

1. **Playable web build** (`game/index.html`, `game.js`, `render.js`,
   `style.css`): camera pan + pinch/mouse-wheel zoom, tap and drag
   selection, move / attack-move / attack / hold orders, a minimap that
   recentres the camera, pause, reset, and a victory banner.
2. **DOM-free fixed-timestep simulation** (`game/sim.js`, 20 ticks/second,
   separate from rendering): grid terrain with movement costs and
   collision, A* pathfinding with replanning, weapon range / minimum range /
   line-of-sight checks, armor-matrix damage with splash falloff, pooled
   projectiles, and elimination victory.
3. **Test map** (64×40 tiles): grass west, dirt east, a north–south river
   (columns 30–33) with a single bridge (rows 18–21) as the only ground
   chokepoint, plus forest and rock clusters. Each side starts with a
   Command Core and 10 units (scouts, tanks, heavy tank, Bulwark mech,
   Lancer mech, Longshot artillery mech, flak tank).
4. **Data catalog** (`data/catalog.json`, browser copy `game/catalog.js`,
   generated by `scripts/build-catalog.js` from `scripts/gen-catalog.py`):
   49 units across all six spec §6 categories (recon/light 10, main battle
   4, artillery/siege 10, anti-air/air 8, support/engineering 9,
   experimental/super-heavy 8), 19 weapons across all twelve spec §8
   weapon families, all eight §7 chassis, all six armor classes and six
   damage types with a full 6×6 armor matrix, 23 structures, and four
   factions (Iron Eden, Xandria, Salvage Clans, Directorate) with rosters.
   Gameplay in this prototype uses a playable subset; the catalog is
   complete as data and is validated, not hardcoded per-unit logic.
   Catalog stats are original values written for this prototype. No
   Rusted Warfare assets, unit names, stats, sprites, or code were copied,
   and the user's reference screenshot was not copied.
5. **Performance architecture from the start**: spatial grid (4-tile cells,
   reused buckets, no per-tick bucket allocation), a pre-allocated
   2,048-slot projectile pool (shots are dropped, never allocated, when
   exhausted), swap-remove cleanup, and pathfinding only on orders or
   target changes — not every tick.

## Test results

Command: `node --test tests/sim.test.js tests/catalog.test.js`
Result: **15/15 PASS, 0 fail.**

- Movement: a tank follows a path and arrives at the ordered tile.
- Pathfinding/collision: a ground path to the far bank uses the bridge
  and never crosses water; a hover path avoids rock.
- Weapon range/LOS: in-range targets take damage, out-of-range targets do
  not, rock blocks line of sight, long-range artillery does not fire
  inside its minimum range.
- Armor/damage: heavy cannon vs Heavy armor = 28 × 0.7; rocket artillery
  splash at half radius = 30 × (1 − 0.6 × 0.5); centre splash is full.
- Combat/victory: a tank kills a scout in range; elimination (all enemy
  units and structures gone) declares the other faction winner.
- Catalog validation: no duplicate ids; every unit weapon/chassis/armor
  reference resolves; every weapon family/damage-type/target class is
  valid with sane numbers; every faction roster has an answer to armour,
  artillery, air, and light-mass; all six §6 categories are represented.

## Stress results (sandbox only — NOT a phone FPS claim)

Command: `node scripts/stress.js` (300 ticks, two blobs attack-moving at
each other on flat grass, 20 ticks/second = a 50 ms per-tick budget).
Repeated runs varied slightly; the recorded run gave:

| Units | Avg ms/tick | p95 ms/tick | Max ms/tick | Alive after 300 ticks | Projectiles active |
|------:|------------:|------------:|------------:|----------------------:|-------------------:|
| 100 | 0.51 | 1.81 | 18.99 | 65 | 11 |
| 300 | 0.89 | 1.30 | 12.00 | 205 | 28 |
| 500 | 1.74 | 2.25 | 5.58 | 342 | 49 |

No winner in 300 ticks at any count (armies were still fighting). Averages
across runs were roughly 0.3–0.5 ms (100), 0.85–0.9 ms (300), and
1.6–1.7 ms (500) per tick on this sandbox VM. These say the simulation
core is cheap at 500 units here; they say nothing about rendering,
touch input, or a phone's frame rate, which were not measured.

## Deviations from the spec (user direction wins)

- **Strict 90-degree top-down** overrides the spec §5 "top-down or
  slightly angled" camera and the §19 eight-direction sprite set. Units
  are drawn from directly above with continuous hull/turret rotation, not
  angled frames. No camera rotation.
- **Standalone game, not a sequel add-on**: the spec document is titled
  "Scrap Dungeon II: Surface Wars", but the user's locked direction is a
  total new game based on the original. This prototype is therefore a
  separate project in `~/workspace/surface-wars/`, reusing the spec's
  factions, units, and systems as design data, not the dungeon crawler's
  code or art.
- **Demo opponent, not AI**: `game.js` sends idle Xandria units on
  attack-move orders every 2 seconds so the test map is playable solo.
  This is not an AI doctrine and must not be described as one.
